# Daemon operation

Build both binaries with `go build -o bin/offscreen ./cmd/offscreen` and `go build -o bin/offscreend ./cmd/offscreend`. Run `bin/offscreen daemon install` to copy `offscreend` from beside `offscreen` (or from `PATH`) into `~/Library/Application Support/offscreen/bin/` and register a KeepAlive LaunchAgent. Reinstall after rebuilding; `bin/offscreen daemon uninstall` stops and unregisters it. Installation preserves `OFFSCREEN_CONFIG` and `OFFSCREEN_STATE_DIR` when set, and passes the installer's `PATH` to launchd so Tart is available. Run without the service exits 70 and asks you to install it; it does not silently start a daemon. Ensure the selected image exists before submitting jobs.

Each `offscreen run` snapshots the submitting CLI process's host environment into its job request (including values containing `=`). The daemon persists this snapshot with the request. It uses the snapshot to expand `[prepare] share` variables and runs `[prepare] run` with that caller's environment, including the caller's `PATH`. Different clients cannot change each other's host preparation environment. The daemon's own environment and `PATH` still control Tart; host environment variables are never forwarded wholesale into the guest (only the explicit `OFFSCREEN_*` task variables are supplied there). Old requests without a snapshot fall back to the daemon's environment. Job requests in the owner-only SQLite state file can contain secrets from the submitting environment; protect that file and its backups accordingly.

By default the service uses `~/Library/Application Support/offscreen/jobs.sqlite` and `offscreend.sock`, with job output in `~/Library/Caches/offscreen/jobs/<id>/`. `OFFSCREEN_STATE_DIR` can isolate both the database/socket and the job directories (use a short path because Unix sockets have a path-length limit). The socket is owner-only. `status` includes terminal records; `logs <id>` replays stdout/stderr, `logs -f <id>` follows live output, `artifacts <id>` prints the directory, and `cancel <id>` waits for VM cleanup. Detached jobs use closed stdin; use a blocking run for interactive stdin and a TTY. After a daemon restart, queued attached jobs fail with code 70 because their stdin attachment was lost; they are not retried with empty input. Queued detached jobs may resume, while active jobs fail as orphaned. Queue deadlines return 75; active failures and daemon errors return 70 unless the guest command itself supplied an exit status. The host lane stays queued with an explicit reason until the idle-gated host executor is installed.
